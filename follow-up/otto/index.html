Where I could add value immediately

Start with the problems already in motion

A few of the problems from our conversations are already concrete enough to start working on while the broader model is being mapped.

Forecasting + seasonality

Build the forecast around the economics of each motion.

SPORT, EVENT and University Athlete should roll into one leadership view without being forced into one probability model.

  • Map the revenue drivers and timing for each business.
  • Separate pipeline probability from event, usage or subscription drivers where needed.
  • Make uncertainty and seasonality visible instead of smoothing them away.
Revenue + system mapping

Understand the business before redesigning HubSpot.

Map the motion from customer and buying model through lifecycle, systems, handoffs, data and reporting.

  • See where the three businesses truly intersect.
  • Identify duplicate logic, broken handoffs and missing context.
  • Decide what should be standardized and what should not.
Baselines + trusted visibility

Get to a forecast and pipeline view leadership can trust.

Start with forecast accuracy, pipeline health, velocity, CRM reliability and the quality of the underlying definitions.

  • Separate knowns, confidence gaps and true unknowns.
  • Show data-confidence issues instead of hiding them.
  • Create a leadership view that gets better as the model improves.
Capacity + friction

Find the work that should not require a person every time.

Look across AEs, Marketing and SMEs for repetitive work, missing context and avoidable manual effort.

  • Distinguish process problems from tooling problems.
  • Use automation or AI only where it improves capacity or decision quality.
  • Prioritize the first few changes by business impact, not novelty.
How I would start

30 / 60 / 90: Understand → Build → Measure

Get to a useful current-state view quickly, improve what is clear, and use evidence from the first changes to shape what comes next.

Days 1–30

Understand + map

Learn how each business creates revenue and how the work moves today.

  • Map SPORT, EVENT and University Athlete from buyer and revenue model through systems, data, handoffs and reporting.
  • Baseline forecast accuracy, pipeline health, velocity and CRM / reporting reliability.
  • Document where the motions should share infrastructure and where they need different logic.
  • Fix high-confidence issues as they surface.
Days 31–60

Build + test

Turn the map and baseline into concrete operating decisions and visible improvements.

  • Align with Travis and JL on shared definitions, decision points and motion-specific exceptions.
  • Stand up a first useful leadership pipeline and forecast view.
  • Fix one or two meaningful funnel, handoff or data problems.
  • Test automation or AI against observed manual work.
Days 61–90

Measure + scale

Measure what changed and use the evidence to set the next priorities.

  • Operationalize the first forecast, pipeline and cross-functional cadences.
  • Measure reliability, capacity, conversion, velocity and decision quality.
  • Adjust the operating model based on actual use.
  • Build the 6–12 month roadmap for data, systems, automation and resourcing.
