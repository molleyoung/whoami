FEATURED BUILD 01

End-to-End Prospecting Engine

Problem

Prospecting was fragmented across signals, enrichment, lists, routing, sequencing, rep execution, and measurement. It was difficult to know who mattered, why now, whether context reached the rep, what reps actioned, and what produced pipeline.

What I built

A connected system spanning signal capture, enrichment, ICP and persona qualification, context, prioritization, Salesforce matching, ownership, rep execution, engagement, outcomes, and resurfacing.

How it works

  1. 01⌁Signals & ContextIntent · web · hiring · engagement
    Enrichment · ICP / persona
  2. 02↑PrioritizeFit · why now · account match
    Ownership · right motion
  3. 03◎Rep ExecutionRep / AE Command Center
    Route · sequence · next action
  4. 04↗Engagement / OutcomeConversation · pipeline · revenue
    Outreach · Orum · email · LinkedIn
↰Feedback / Resurface

Outcome becomes the next input—learn, reprioritize, and return the right account to the motion.

RETURN TO PRIORITY ↑

Feedback / Resurface loops outcomes back into future signals and prioritization.

Inputs and execution can include website, intent, hiring, procurement, and engagement signals; firmographic and technographic enrichment; Salesforce working views; the Rep / AE Command Center; Outreach, Orum, email, and LinkedIn.

Impact / Evidence

The TitanX pilot became a forcing function for a repeatable, quality-first engine across enrichment, targeting, Salesforce loading, routing, sequencing, and measurement. TitanX remains one supporting pickup-scoring experiment—not the proof title or the whole strategy.

FEATURED BUILD 02

Closed Won Review Agent

Problem

Closed Won deals could trigger shipping, invoicing, and provisioning without a validation gate. Missing or incorrect data created downstream risk, delays, and manual RevOps cleanup.

What I built

An automated validation layer between Closed Won and downstream execution. Clean records can be approved automatically; issues return specific remediation guidance.

How it works

SALESFORCE✓Closed WonRecurring review
CONTROL POINTValidation~47–53 checks before downstream execution

Deal data · commercial terms · billing readiness · provisioning inputs

PASSRelease downstreamFulfillment · billing · provisioning
ISSUERemediateSlack guidance → correct → recheck
↶ ISSUE returns to validation

AI is used selectively for fuzzy checks such as address validation and plain-English remediation guidance.

Impact / Evidence

  • Mean time-to-approval: ~2.6 days to under 1 day
  • Same-day approval rate: ~60% to ~90%
  • Issues surface before shipping, invoicing, or provisioning
  • Runs unattended on a recurring schedule
  • No additional workflow required from Sales

Stack

Salesforce · Python · Claude · Slack · g-gremlin · launchd

FEATURED BUILD 03

Event Import Pipeline

Problem

Tradeshow lists required manual cleaning and entered routing with limited control over duplicates, existing-account matches, customers, open opportunities, existing SQLs, and contacts already being worked.

What I built

A reusable, configuration-driven event pipeline with governed matching, exclusions, operator review, activation, and retained intermediate states.

How it works

  1. 01▤Raw InputEvent list
    Retained source file
  2. 02⌁Governed ProcessingNormalize · dedupe · match
    Exclusions and retained states
  3. 03QAOperator QAHuman review checkpoint
    Approve activation
  4. 04↗ActivationSalesforce · campaign · route
    Outreach sequence

Guardrails Customers · open opportunities · existing SQLs · already sequenced

YAML controls event-specific behavior. The pipeline supports multi-strategy matching, LeanData or manual routing, Outreach enrollment, and auditable intermediate run files.

Impact / Evidence

  • 10+ events processed
  • Roughly 5 to 600+ badge scans per event
  • Reusable configuration, matching, exclusions, routing, sequencing, and auditable files

Stack

Python · YAML · Salesforce · g-gremlin · LeanData · Outreach · Claude Code · Confluence

FEATURED BUILD 05

Analytics & Revenue Intelligence

Problem

Leadership answers were fragmented across Salesforce reports, manual weekly assembly, changing definitions, static reporting, recurring analysis, and conversational questions—with no reliable memory of prior delivered views.

What I built

A revenue-intelligence delivery system organized around Explore → Receive → Ask, with all three modes grounded in shared GTM data, documented definitions, and business logic.

How it works

01 / EXPLORE▥Executive GTM SummaryInteractive HTML
Filter · drill down · inspect
02 / RECEIVE↻Automated GTM InsightsRecurring analysis
Confluence + Slack delivery
03 / ASK?LLM Analytics InterfaceData Catalog + Business Knowledge
→ Context Layer → LLM
SHARED FOUNDATIONGTM Data + Business Logic / DefinitionsOne trusted base, three consumption modes
EXPLORE
Executive GTM Summary

A weekly executive view of ARR and growth, pipeline and forecast, customer health, funnel, and sources. Filters and record drilldowns sit inside self-contained interactive HTML.

  1. Salesforce
  2. Python pull
  3. Integrity gate
  4. HTML dashboard
  5. Publish / archive

Builds compare with the prior version; empty core data or >20% headline movement can hold publication. Historical builds, versioned definitions, and checksum-verified delivery preserve an auditable record.

RECEIVE
Automated GTM Insights

Bi-weekly automated pipeline analysis moves from Tableau export through statistical analysis and Claude Opus narrative generation into recurring Confluence and Slack delivery.

ASK
LLM Analytics Interface

Executives can query Salesforce through the connected MCP. Trust comes from three distinct layers:

  • Data Catalog — what exists and what it means
  • Business Knowledge — how the motion and metrics work
  • Context Layer — runtime definitions, mappings, instructions, guardrails, and traps

Impact / Evidence

  • One weekly executive view instead of manual assembly
  • Scheduled refresh with an integrity gate that has held bad or partial builds
  • Auditable historical builds and versioned metric definitions
  • No new BI vendor, per-seat BI cost, or dedicated BI engineer required

Stack

Salesforce · Python · HTML · CSS · JavaScript · launchd · Confluence · Google Drive · Google Cloud · Tableau · Claude / Claude Code · Salesforce MCP

Delivery currently includes Confluence and Google Drive. The authenticated Google Cloud viewer is a future delivery model, not presented as fully shipped.
